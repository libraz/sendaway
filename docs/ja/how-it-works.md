# 動作の仕組み

このページでは、shim の判断から結果の記録まで、1 回のリモート実行を順に追います。

## 1. 判断

shim は `.sendaway.yml` を探し、コマンドラインをルールに照合して（[設定](configuration.md#remote-と-local-のルール書式)を参照）、次の 3 つのうちどれかの経路を取ります。

- `.sendaway.yml` がない場合、または `SENDAWAY_PASSTHROUGH` に空でない値が設定されている場合：shim のプロセスを本物のバイナリで置き換え、そのまま実行します。
- `local:` に一致した場合、またはどれにも一致しなかった場合：環境に `SENDAWAY_PASSTHROUGH=1` を加えて、本物のバイナリを起動します。そのプロセスが起動するコマンドも、このためローカルに留まります。
- `remote:` に一致した場合：以下のリモート実行です。

本物のバイナリは、shim ディレクトリを飛ばして PATH を検索して見つけます。`sendaway run <command>` はルールを無視してリモート経路を強制し、`sendaway local <command>` はローカル経路を強制します。

## 2. 事前条件

何かを送る前に、shim はプロジェクトのルートを確認します。`.sendaway.yml` が git のトップレベルにあり、`.git` がディレクトリである必要があります（git worktree は拒否されます）。その後、実行記録のディレクトリを作成するため、失敗した実行でも内容を調べられます。

shim はプロジェクトごとのローカルロックを取得します（キーはルートのパスです）。同じプロジェクトの別の実行がロックを持っている間、shim は `waiting for lock (held by: <argv>, <time>, run <id>)` と表示して待ちます。ロックは、保持しているプロセスがどのような形で終了しても解放されます。

## 3. ファイルセット

shim は git を使って 3 つのセットを作ります。そのため、否定パターン、`.git/info/exclude`、`core.excludesFile` は git と同じように働きます。

- **マニフェスト**：作業ツリーのうち、git が追跡しているファイルか、無視していないファイルを、ソートして並べたものです。ローカルで削除された追跡ファイルは含まれません。
- **無視セット**：git が無視している未追跡のパスです。送られることはなく、ホスト上にある同名のコピーにも手を付けないため、ビルドディレクトリは実行をまたいで残ります。
- **シークレットセット**：シークレットのルールまたは `exclude:` によって送られないマニフェスト内のファイルです（[セキュリティ](security.md#シークレットファイル)を参照）。マニフェストから取り除かれ、`not sent (secret-like)` に列挙されます。

マニフェストの作成時に、git サブモジュール、ネストしたリポジトリ、ディスク上で NFC 形式で保存されていないファイル名があると、実行は失敗します。リポジトリの外を指すシンボリックリンクは送られますが、ホスト上では宙に浮いた状態になり、警告で名前が示されます。マニフェストが 256 MiB を超えると、大きい順に 5 つのファイルを挙げた警告が出ます。

## 4. セッション

実行には ssh 接続を 1 本使います。接続はホスト上で `sendaway remote-exec` として起動され、次回以降の実行がすばやく再接続できるよう、ssh の control master によって 10 分間バックグラウンドで維持されます。セッションは次の順で進みます。

1. **hello**：ホストが、プロトコル、バージョン、OS、アーキテクチャを送ります。プロトコルが異なる場合、実行は `protocol mismatch: local sendaway <version> speaks protocol <n>, remote sendaway <version> speaks protocol <n>; install the same version on both sides` というメッセージで停止します。
2. **request**：shim が JSON を 1 行送ります。内容は、実行 ID、ルート、作業ディレクトリ、コマンド、転送する環境、マニフェスト、prepare のルール、`pull:` と `artifacts:` のパス、出力を統合するかどうか、送信時刻です。
3. **リモートロック**：ホストがプロジェクトのルートに対するロックを取得します。別のセッションが保持している間、ホストは `waiting for remote lock (held by run <id>, <time>)` と報告します。ここでホストは時計も比較します。差が 2 秒を超えると通知し、60 秒を超えると `remote clock differs from local by <d> (limit <d>); sync the clocks` で実行を終了します。
4. **削除**：ホストは、前回の実行が送り、今回は送られないファイルを自分のコピーから削除し、その結果空になった親ディレクトリも削除します。パスの種類が変わっている場合（ディレクトリが必要な場所にファイルがある、ファイルやシンボリックリンクが必要な場所にディレクトリがある）は、push で置き換えられるようにそのパスを片付けます。ホストにしか存在しないディレクトリは削除されません。リモートの状態がない場合、ホストは `remote state missing; locally deleted files may linger — run 'sendaway forget' to start clean` と通知します。
5. **ready**：ホストが push の準備ができたことを報告します。
6. **push**：2 つの rsync が並列で動きます。作業ツリー用と `.git` 用です。ツリーの rsync はルートを基準とし、無視セット、シークレットセット、`exclude:` のエントリを除外します。`.git` の rsync は古いファイルを削除しますが、`config`、`FETCH_HEAD`、`hooks/`、`logs/`、`*.lock`、`objects/tmp_*` には触れません。rsync の終了コード 24（ファイルの消失）は許容され、`some files vanished during sync` として報告されます。
7. **pushed**：shim が push の完了をホストに伝え、開始行と警告を表示します。ホストは、送られたものの記録としてマニフェストを保存し、リモートを持たない最小限の `.git/config` を書き込みます。
8. **prepare**：入力が変化したルールが実行されます（[設定](configuration.md#prepare)を参照）。
9. **コマンド**：ホストがコマンドを起動し、その出力を中継します。

`pushed` より前に中止されたセッションでは、ホストに保存されたマニフェストは元のままです。

## 5. コマンドの起動方法

ホストは、コマンドを専用のプロセスグループで起動します。stdin は `/dev/null` で、作業ディレクトリは shim が使っていたもの（なければ作成します）です。起動はユーザーのログインシェル経由です。

```
$SHELL -lc 'exec env -- "$@"' sendaway NAME=value ... command args...
```

ログインシェルはホストのプロファイルを読み、ツールチェーン用の PATH を設定します。続く `env` が、プロファイルの設定の上に転送された変数を重ねるので、転送された `MAKEFLAGS` や `GOFLAGS` が優先されます。

シェルが起動時に持つ環境は、ゼロから組み立てられます。ホスト上の ssh セッションにある `HOME`、`USER`、`LOGNAME`、`SHELL`、`PATH`、転送された変数、そして `SENDAWAY_PASSTHROUGH=1` です。ssh が転送したかもしれないロケール変数を含め、それ以外は何も引き継がれません。許可リストは[セキュリティ](security.md#環境変数)を参照してください。

## 6. 出力

ホストは、コマンドの出力をフレームに分けて送ります。stdout は `out`、stderr は `err`、ホストから来る sendaway 自身のメッセージは `note` です。shim は `out` を自分の stdout に、`err` を自分の stderr に書き、`note` は stderr に `[sendaway]` の行として書きます。

- **統合**：shim の stdout と stderr が同じファイルの場合（同じ端末、または `2>&1` で 1 つのファイルへ向けた場合）、ホストはコマンドの stdout と stderr を 1 本のパイプにまとめます。そのため、相対的な順序は出力されたとおりに保たれます。
- **分離**：別のファイルの場合、ホストはパイプを 2 本保ちます。各ストリームの中の順序は保たれますが、2 つのストリームの間の順序は保証されません。

表示されたものはすべて、sendaway 自身の行も含めて、実行の `output.log` に追記されます。shim と端末の間にあって stderr の順序を入れ替えるものがあると（[コーディングエージェント](coding-agents.md#出力フィルタ)を参照）、`[sendaway]` の行が出力に対して前後します。

## 7. 中断と生存確認

shim は SIGINT、SIGTERM、SIGHUP を処理します。最初の 1 つを受けると、cancel フレームを送ってセッションを閉じ、終了まで最大 10 秒待ち、トレーラーを `killed by signal <n>` として表示し、実行を記録してから、同じシグナルで自分自身を終了させます。

ホストでは、cancel フレームを受けるとコマンドのプロセスグループに SIGINT を送ります。それ以外の停止の原因（接続が閉じた、出力パイプが壊れた、無応答）では SIGTERM を送ります。猶予の 5 秒を過ぎてもグループが動いている場合は SIGKILL を送ります。その後、ホストはロックを解放します。

shim は 5 秒ごとに ping を送ります。ホストは、request の後のどの段階でも（ロック待ち、push、prepare、コマンドの実行中）、30 秒間何も受信しなければセッションを停止します。したがって、ネットワークが切れても、無音の状態が最大 30 秒続いた後にリモートの作業は止まります。`setsid` で新しいセッションへ移ったプロセスはグループの外にあるため、停止されません。

## 8. 完了

コマンドが終了すると、ホストは何を持ち帰るかを決めます。

- 終了コード 0 でシグナルなし：`pull:` のパス。
- それ以外：`artifacts:` のパス。

ホストはさらに、同期されたファイルのうち、サイズか更新時刻が変わったもの、または存在しなくなったものを、回収したものを除いて一覧にします。shim は回収したファイルをコピーした後、次を表示します。

1. その一覧が空でなければ、変更ファイルの警告：`remote run modified N synced files (not copied back): <up to five paths> … and K more — add this target to local: or list the files in pull:`。追跡ファイルを書き換えるコマンド（フォーマッタ、コードジェネレータ）は `local:` に入れるか、その出力を `pull:` に入れます。
2. トレーラー：`[sendaway] <host> exit N · <seconds>s · run <id> · log <path>`。コマンドがシグナルで死んだ場合は、`exit N` の代わりに `killed by signal N` となります。

`pull:` で拒否されたパスのように、回収中に失敗すると、理由を表示し、実行を失敗として記録して、終了コード 125 で終了します。

その後 shim は、コマンドと同じ形で終了します。コマンドの終了コードで終了するか、同じシグナルで自分自身を終了させます。shim のプロセスでそのシグナルが無視されている場合は、代わりに 128 にシグナル番号を足した値で終了します。

## 9. 実行記録

実行ごとに、`${XDG_STATE_HOME:-~/.local/state}/sendaway/runs/<id>/` というディレクトリ（モード 0700）が作られ、次が入ります。

| ファイル | 内容 |
|---|---|
| `output.log` | 実行中に表示されたすべて |
| `meta.json` | コマンド、作業ディレクトリ、ルート、ホスト、時刻、終了コード、シグナル、変更ファイル、ツリーのフィンガープリント、エラーの文面 |
| `artifacts/` | 失敗後に回収したファイル |
| `fetched/` | `sendaway fetch` で持ち帰ったファイル |

`meta.json` に環境変数が含まれることはありません。実行 ID は `r-20250101-120000-ab12` のような形で、UTC の開始時刻を含みます。

記録のたびに、新しい 100 件を超える実行と、14 日より古い実行が削除されます。`sendaway runs` は記録を一覧し、`sendaway last` は最新の 1 件を要約します。どちらも、プロジェクトの現在のファイルサイズと更新時刻が、その実行が見たものと異なる場合、その実行に `(tree changed since this run)` を付けます。

ローカル実行に切り替わった実行は、記録を残しません。

## 10. フォールバック

ホストが hello を返す前にネットワーク経路が失敗すると、コマンドは代わりにローカルで実行されます。shim は `[sendaway] <host> unreachable (<reason>), running locally` と表示し、実行記録を破棄し、ロックを解放して、`SENDAWAY_PASSTHROUGH=1` と下げた優先度（nice 10）で本物のコマンドを起動します。

理由には、ssh のメッセージのうち一致したものが入ります。`Could not resolve hostname`、`Connection timed out`、`Operation timed out`、`No route to host`、`Connection refused`、`Network is unreachable` のいずれかです。

フォールバックは `Permission denied`、`Host key verification failed`、`REMOTE HOST IDENTIFICATION HAS CHANGED` には適用されません。同じ ssh の出力に到達不能のメッセージが含まれていても同様です。これらは ssh 自身のメッセージとともに、exit 125 で実行を終了させます。hello より後の失敗もフォールバックしません。ホストがすでに作業の一部を持っている可能性があるためです。push が終わる前に接続が切れると `connection lost during sync — nothing ran` と報告され、それ以降に切れると `connection lost during run — result unknown` と報告されます。どちらも 125 で終了します。
